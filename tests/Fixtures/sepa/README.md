# SEPA-Schema für Tests

`pain.008.001.08.xsd` – ISO 20022 Message Definition *CustomerDirectDebitInitiationV08*
(Namespace `urn:iso:std:iso:20022:tech:xsd:pain.008.001.08`), so wie die
ISO-20022-Registration-Authority sie veröffentlicht („Generated by Standards Editor … 2019 Feb 14“).
Gegen dieses Schema prüft `tests/Service/Beitraege/Pain008Test.php` jede erzeugte
Lastschriftdatei (docs/spec/08-beitraege.md §4).

- **Herkunft:** ISO 20022 Message Catalogue (iso20022.org). Die hier abgelegte Kopie stammt –
  wie das pain.001-Schema in Vereinsbelege – aus dem Repository `raphaelm/python-sepaxml`
  (`sepaxml/schemas/pain.008.001.08.xsd`).
- **Änderung:** nur die Zeilenenden (CRLF → LF, wegen `.gitattributes`), der Inhalt ist unverändert.
  SHA-256 der Quelldatei mit CRLF: `7edf4e4ce34c47a5567af6a327e22af4ed4007f715822af9f353c94ecc10f5ba`,
  SHA-256 dieser Datei: `3b2efe2239fceea22b17eb980df58c8b80db7322cf7781f8fd64ee8d17696210`.
- **Lizenz:** ISO-20022-Nachrichtendefinitionen und ihre XML-Schemas stellt ISO kostenfrei zur
  Verwendung bereit (Nutzungsbedingungen auf iso20022.org); sie sind nicht Teil des
  Anwendungscodes und kommen **nicht** ins Release-ZIP – nur die Tests lesen sie.

Das Schema ist die allgemeine ISO-Fassung. Die zusätzlichen Regeln der Deutschen Kreditwirtschaft
(DFÜ-Abkommen Anlage 3, Version 3.7: SEPA-Zeichensatz, Namen ≤ 70 Zeichen, Verwendungszweck
≤ 140 Zeichen, nur EUR, `ChrgBr` = `SLEV`, Service-Level `SEPA`, Lokalinstrument `CORE`,
Gläubiger-ID unter `CdtrSchmeId` mit `SchmeNm/Prtry` = `SEPA`) prüfen
`App\Service\Beitraege\Sepa\Pain008` selbst und der Test strukturiert. Das DK-eigene Schema ist
nicht frei abrufbar; die Abnahme mit einem echten Upload ins Online-Banking bleibt ein Prüfpunkt
(docs/fachlichkeit.md: „Erste Datei als Test im Online-Banking hochladen“).
